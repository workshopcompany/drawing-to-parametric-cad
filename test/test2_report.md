# test2 보고서 — 실도면 → 파라메트릭 CAD 파이프라인 테스트 (2차, Osstem Bracket MIM Proto)

## 1. 테스트 개요

- 목적: 2D 도면 이미지 입력 → 질문(Q&A) → FreeCAD 파라메트릭 모델(.fcstd) 생성 파이프라인의 두 번째 실전 테스트.
  test1(기어)이 표준 부품 중심이었다면, test2는 비표준 곡선 훅 + 기능 슬롯을 가진 복잡한 MIM 브래킷으로 검증.
  슬롯은 가장 중요한 기능부 (와이어 삽입부)라 정확 기하 (직사각형·각도·폭)를 별도 게이트로 검증.
- 입력: 정면도 (깨끗한 도면, 1552×1228) + 단면 A-A + 평면도 + 사용자 트레이스 (JSON, 빨간/파란 윤곽선, 초록 채움) + 스냅 도구 export.
  보안상 원본 도면 이미지, 사용자가 주석한 이미지 (빨간/파란/초록), 도면 배경 오버레이는 본 보고서, zip, GitHub 업로드 어디에도 포함하지 않음. 생성물만 포함.
- 출력: 최종 모델 test2_body_v12.fcstd (+ STEP), 본 보고서, test2_results.zip, 윤곽 스냅 도구 (별도 HTML).
- 도구: FreeCAD 1.1.4 (AppImage), PartDesign (Sketch → Pad), verify_model.py 검증 하네스, 윤곽 스냅 도구 (web artifact).
- 기간: 2026-10-27 ~ 2026-10-28 (집중 작업은 10-28 당일).

## 2. 최종 모델 사양 (v12, 확정)

- 단품, MIM 브래킷 본체 (베이스 + 크라운 상부). 와이어는 별도 삽입 부품이라 본체 모델에 솔리드로 만들지 않음, 슬롯은 빈 공간.
- 베이스: 단면 3.6×3.15 (좌 R0.75 / 우 R0.8, 24° 대각선), 높이 2.8.
- 상부: 하나의 연결된 크라운 영역 (왼쪽 훅 + 중앙 덩어리 + 오른쪽 훅). 전체 너비 4.800, 피크 4.500, 크라운 1.7 (베이스 위),
  훅 팁 좌 3.6 / 우 3.77, 상부 두께 (Y) 2.124, 훅 두께 0.5.
- 슬롯 (가장 중요한 기능부): 위가 열린 직사각형 홈 2개 (닫힌 구멍 아님, 별도 포켓 아님).
  폭 0.500 정확 (2군데), 각도 좌 +35.00° / 우 -55.00° (수평 기준, 명목 정확), 안쪽 끝 모서리 90°/90°, 직선 변,
  상부 두께 전체 (Y 2.124) 관통. Y ±0.25 포켓 아님 — Y 깊이는 후속 결정 사항으로 남김 (6절 참조).
- 일반공차 ±0.1 (치수 강제 항목은 ±0.02).
- 체적: 36.514 mm³, 단일 유효 솔리드.
- 피처 트리: Sketch_Base → Pad_Base → Sketch_Upper (12 edges) → Pad_Upper.
- Y=0 단면: 닫힌 선 1개, 길이 23.465 mm.
- 바운딩박스 (STEP 기준): X -2.4031..2.4076 (4.8107, +0.0107), Y ±1.575, Z 0..4.4919 (-0.0081).
  FreeCAD BSpline BoundBox는 폴 기준으로 크게 나오므로 STEP/단면 기준을 사용 (4절 E11 참조).

## 3. 검증 결과

- verify_model.py: OVERALL PASS (스케치 닫힌 와이어, 피처별 유효 솔리드 + 체적 > 0).
  단, harness의 OVERALL PASS는 solids ≥ 1이면 통과라 단일 솔리드는 별도로 명시 확인 (v6 교훈).
- STEP 독립 재독: solids 1, valid True, volume 일치, Y=0 단면 1 wire.
- 모델-vs-도면: 정면 오버레이 + 초록 루프 대조 + 슬롯 확대 오버레이 (직사각형·폭·각도 확인).
- 슬롯 확대: 직선 변, 90° 모서리, 도면 슬롯 선 추적 확인 (강제 후 선 차이: 좌 최대 0.026 mm, 우 최대 0.003 mm, 4절 E9 참조).

## 4. 테스트 이력 — 오류와 해결방안 (핵심)

### v2 ~ v5 (요약, 두-팔 토폴로지 시절)

- v2: 베이스만 도면과 맞고 훅은 안 맞음 (사용자 지적). 중심선 + 오프셋 근사로는 도면의 단일 검은 윤곽 곡선을 충실히 따라가지 못함.
- v3: 사용자 전면 거부 ("하나도 매칭이 안되었어"). 왼쪽 중심선 이동만으로는 부족, 윤곽 자체를 도면에서 가져와야 한다는 요구로 전환.
- v4/v5: 오른쪽 피크 이동, 왼쪽 굽힘 수정으로 치수 (너비 4.788, 오차 0.012)까지는 맞췄으나, 트레이스 매칭 수는 그대로 (18/39 ≤8px).
  교훈: 시드 모델과의 편차 감소는 정답이 아님, 시드 자체가 틀리면 소용없음.

### E1. v6 단일 솔리드 실패 — 루트→피크 채움의 자기교차

- 현상: 본체는 유효하나 2 solids (본체 30.083 + 떠 있는 오른쪽 위 로브 0.722). 전체 30.805 mm³, Y=0 단면 2 wires.
  verify_model.py OVERALL PASS가 떴으나 단일 솔리드 게이트에서 실패 (harness는 solids ≥ 1이면 PASS).
- 원인: 오른쪽 루프 자기교차 (간선 14, 21). 베이스 뿌리→피크 채움 (root→peak fill)이 루프 자신의 팁/안쪽 간선과 교차.
  채움 대안이었던 다른 오른쪽 토폴로지 (v3 꼬리 + L4 외곽 + 동일 채움)도 자기교차.
- 해결: 루트→피크 채움을 폐기. 이후 모든 빌드는 채움 없이 밴드 루프 / 초록 루프만 사용.
  단일 솔리드는 harness PASS와 별도로 명시 확인하는 규칙으로 고정.

### E2. v7 직선 절단 — 브리지 + 코드 닫힘 패드 (사용자 거부)

- 현상: 게이트는 전부 통과 (단일 솔리드, 35.058 mm³, 너비 4.874)했으나 사용자가 거부 ("왜 저렇게 자르는거야").
  정면 프리뷰에서 훅이 네모/세모로 보임 (오른쪽 훅은 삼각형, 왼쪽 훅은 블록).
- 원인: 각 패드 (ArmLeft / ArmLeftOuter / ArmRightBand / ArmRightPeak)를 직선 코드로 닫음.
  오버레이에 빨간 수직 코드, 자홍 파선 수직 코드, 초록 수직 코드, 파란 대각 코드가 훅 밴드를 가로질러 보임.
  사용자가 15:51에 브리지를 승인했음에도, 결과물의 절단 형태는 거부됨 (승인 ≠ 결과 수용).
- 해결: 코드 닫힘을 전면 금지. 밴드는 하나의 루프로 (외곽 + 팁 컬 + 안쪽 + 베이스 윗변), 직선 코드는 베이스 윗변 실제 간선과 15px 미만 단편 연결만 허용.
  v8은 이 규칙으로 중단 (아래 E3), v9/v10/v11/v12는 코드 없이 초록 루프에서 출발.

### E3. v8 중단 + "다리" 용어 혼란 — 존재하지 않는 선을 두 번 요구

- 현상: v8은 엄격 무코드 규칙으로 중단 (파일 없음). 밴드 루프가 빨간/파란 + 베이스 윗변만으로는 닫히지 않음.
  남은 간격 2곳: 왼쪽 바깥 (73,199)→(89,312), 114.1px/0.720mm; 오른쪽 바깥 (764,158)→(637,312), 199.6px/1.272mm.
  두 복도 모두 검은/빨간/파란 잉크 0px.
- 원인 (용어): "다리"라는 말이 사용자에게 별도 부품처럼 들림 ("뭘자꾸 다리를 찍어달라는건지 모르겠는데?").
  주석 이미지로 설명 (훅 바깥선 = 팁→베이스의 훅 테두리, 별도 부품 아님)하고 용어를 "훅 바깥선"으로 바꿈.
  같은 두 간격을 v7 중단 때와 v8 중단 때 두 번 물은 것도 신뢰 비용 (새 요구가 아니라 같은 미해결 2곳).
- 원인 (토폴로지): 애초에 "다리"가 존재하지 않았음. 훅 두 개가 따로 베이스에 붙는 줄 알았으나, 실제는 가운데가 연결된 하나의 형상 (아래 E4).
- 해결: 다리 요구를 철회. 사용자가 초록을 채워서 본체를 직접 보여준 뒤 (E4), 다리 없이 초록 루프로 빌드.

### E4. "갭이 비어있다"는 가정 오류 — 중앙 덩어리가 채워져 있음

- 현상: v9 이전까지 훅 사이 (X -0.88..+0.88, 베이스 위)를 빈 갭으로 가정 (비전 모델의 윗선 판단 + 검은 손그림 + 빨간선 본체 확인을 갭 비움으로 해석).
- 원인: 사용자가 초록으로 채운 이미지 2장 (도면 위 초록 + 초록 단독, 동일 크롭, 초록 IoU 0.995)으로 반증.
  측정: 갭 아래쪽 (x272..544, y180..312) 초록 100%, 베이스 윗변 띠 95.7% 초록, 훅 아래 오목한 곳 ~90% 흰색 (빈 바깥).
  윗변은 W자 (왼쪽 피크 → 왼쪽 슬롯 홈 → 가운데 피크 → 오른쪽 슬롯 홈 → 오른쪽 피크).
- 해결: 본체 상부를 하나의 연결된 크라운 영역으로 재정의 (왼쪽 훅 + 중앙 덩어리 + 오른쪽 훅 + 베이스 띠).
  갭 절단 금지, 훅 아래 오목한 곳 채움 금지. v7 브리지가 오목한 곳을 채워서 네모/세모로 보인 이유가 여기서 설명됨.
  v9는 초록 마스크 경계 (DP ≤2px, 잉크 ≤10px 스냅, 잉크 없으면 초록 유지)를 루프로 Pad Y 2.124, 베이스 윗변에서 닫음.

### E5. 자동 윤곽 추출 실패 — 사용자 눈 + 스냅 도구로 전환

- 현상: 스네이크 / 필터 스네이크 / 방향 스냅 / 슬롯 제외 방향 스냅이 v5 시드 대비 편차는 줄였으나 (방향 스냅 좌 평균 4.8px, 우 2.3px) 사용자가 전부 오판.
  사용자 지시: "내가 찍은 포인트랑 안맞도 윤곽을 도면에서 가져와야지" (내 포인트와 안 맞아도 윤곽은 도면에서 가져와야 함).
  정제 윤곽 (스켈레톤 잉크 스냅, 평균 이동 2.4px)은 "선이 왜 삐뜰빼뚤하지? 이건 도저히 못쓰겠어"로 거부 (날것 1px 잉크, 평활 의도적 보류가 잘못된 절충).
  플러드필 (밴드 내부가 끊김으로 배경과 연결) / 잉크 워크 (시작 검출 실패, y700~760 행에 20~30px 간격 런 + 파선)도 실패.
- 해결: 자동 스냅을 답으로 내지 않음. 사용자가 눈으로 지정하는 웹 스냅 도구로 전환 (13:28 지시).
  도구 진화 (사용자 주도): 점 선택 → 선 선택 (선 중간 클릭 → 접선 추적, 교차점 정지, 파선 간격 브리지, 선 내 평활만) →
  끝점 드래그 (선을 따라서만 이동) → 끝점 병합 (끝점끼리 스냅 + 선 중간에 붙이기) → 직선 그리기 → 선택 선 삭제 (이미 존재, 안내로 해결) →
  채움 미리보기 (닫힌 윤곽 초록 채움, 닫힘/열림 + 면적 표시, 안쪽 닫힌 윤곽은 비움) → 수동 칠하기 (붓 + 지우개, JSON fills + PNG 내보내기) →
  터치 채움 (붓 유지, 면 터치 시 그 면 전체 채움, 번짐 방지 거부, 선 틈 메우기 0~6px) → 예시 도면 (현재 도면이 아닌 연습용 도면 + 윤곽/채움 예시 이미지 상시 표시).
  빌더 기능 테스트 통과 ≠ 실시간 검증 (캔버스 드래그 칠하기 / 터치 채움은 사용자 실시간 확인 필요, 6절 참조).

### E6. JSON 분실 주장 오류 — 채팅 기록 확인 전 단정 금지

- 현상: "사용자가 준 JSON이 저장되지 않았다"고 말했으나 틀림. 사용자가 "실제로 찍은 json 복사해서 줬었잖아.."로 지적, 채팅 DB에서 회수 (메시지 96ade5c2).
- 해결: 사용자가 준 트레이스/JSON은 즉시 워크스페이스 파일로 저장. 분실 주장은 채팅 기록/DB 확인 전에는 하지 않음.
  교훈은 본 테스트 내내 유지 (v3 JSON, 초록 이미지 등 즉시 파일화).

### E7. 흐릿한 선 누락 의심 — 임계값 스윕으로 부재 확인

- 현상: 바깥 다리 복도에 선이 흐릿하게라도 있는지 의심 (놓친 선이 있으면 트레이스 요구 자체가 틀림).
- 해결: 깨끗한 도면 + 원본 도면 모두에서 임계값 스윕. 왼쪽 복도 <240까지 0px, 오른쪽 복도는 <240에서 베이스 윗부분 헤일로 (y290..309)만, <220에서 1px, <200에서 0px, 왼쪽 <255는 잡음만.
  결론: 바깥 다리 선은 어느 임계값에서도 없음 (진하게도 흐릿하게도 없음). 이후 E4에서 다리 자체가 없음이 확정됨.

### E8. 슬롯 스펙 오류 — v5 스펙 vs 도면 (각도·위치·길이·Y 깊이·폭)

- 현상: v10까지 슬롯 홈이 도면과 안 맞음. v10 노치: 왼쪽 폭 0.5161, 오른쪽 폭 0.3748 (스펙 0.500과 차이), 곡선 스플라인 노치 (직사각형 아님).
  v5 스펙 (중심 (±1.21, 3.54), 0.5×1.2, 양쪽 35°, Y ±0.25 포켓)이 도면과 다름.
- 원인: v5 스펙은 와이어/훅 교차 추정치였고, 도면의 슬롯 직사각형 (검은 잉크 선 + 치수 0.5×2, 호 55°/35°, 수평 1.52×2)과 다름.
  도면 측정: 각도가 두 슬롯이 다름 (왼쪽 수평 기준 약 35°, 오른쪽 약 55°, 비대칭 Λ — 양쪽 35°라는 과거 해석은 틀림).
  1.52 치수는 어떤 정의로도 잉크 중심을 X ±0.88로 맞추지 못함 (안쪽 끝 중심 좌 -1.200 / 우 +0.987, 직사각형 중심 좌 -0.801 / 우 +0.774).
- 해결 (v11): 슬롯 홈만 정확 직사각형으로 교체 (직선 평행 변, 직각 안쪽 끝, 스플라인 둥글림 없음, 폭 0.500 정확 양쪽).
  나머지 v10 스플라인, 베이스, Y 깊이 (통과 홈)는 그대로. 슬롯 확대 오버레이로 직사각형·폭·각도를 눈으로 검증.
  v5 스펙은 도면 치수 + 잉크로 대체됨 (우측 각도 -35° → -54.66°, 안쪽 끝 Z +0.355/+0.284, X +0.010/-0.223, 길이 1.2 → 0.957/0.736).

### E9. 왼쪽 슬롯 각도 명목 vs 잉크 (35° vs 33.73°) — 사용자 결정으로 강제

- 현상: v11 왼쪽 슬롯을 잉크에 맞추면 33.34° (중심선 33.73°, 변 32.41°/33.88°)로 명목 35°와 -1.66° 차이.
  오른쪽은 -54.66°로 명목 -55°와 +0.34° 차이 (거의 일치).
- 해결: 숨기지 않고 보고, 사용자가 결정 ("각도 정확하게 맞춰줘 35도, 55도").
  v12에서 각 직사각형을 중심 기준으로 명목 각도로 회전 (좌 +35.00°, 우 -55.00°, 오차 0.00).
  강제 후 선 차이: 좌 최대 0.026 mm (중심선 기준, 선 두께 감안 시 선까지 최대 0.017 mm), 우 최대 0.003 mm.
  기능부 (와이어 삽입)는 명목 각도가 우선, 형상은 잉크가 우선이라는 균형 규칙으로 정리 (차이는 반드시 보고).

### E10. 오버레이 작도 버그 — 단면 간선 순서

- 현상: v9 첫 오버레이에서 단면 간선을 파일 순서대로 연결해 노치 내부에 가짜 코드가 그려짐.
- 해결: 간선을 끝점 연결성으로 체인해 순서 있는 폴리라인으로 만듦 (정렬 후 길이가 FreeCAD 와이어 길이와 정확히 일치, v9 23.458 mm).
  이후 모든 오버레이는 체인 후 작도, 가짜 코드와 모델 코드를 구분해서 확인.

### E11. BSpline BoundBox 폴 아티팩트 — STEP/단면 기준

- 현상: FreeCAD에서 BSpline 패드의 BoundBox가 폴 기준으로 크게 나옴 (v10 4.846/4.516, v11 4.887/4.537, v12 4.8902/4.5367).
- 해결: 치수는 STEP 테셀레이션 / 단면 기준으로 측정 (v12: 너비 4.8107, 높이 4.4919).
  GUI BoundBox 수치를 그대로 치수로 보고하지 않음.

## 5. 파이프라인에서 얻은 교훈 (시행착오 축소 방안)

- 도면 해독표 선행: 빌드 전 모든 치수/지시를 피처에 매핑 + 확신도 표기, 사용자 확인 후 빌드 (test1 합의, test2에도 적용).
- 표준 부품 표준 도구: 기어 → InvoluteGear, 나사 → 탭드릴 + 탭. 비표준 곡선은 스플라인, 기능 슬롯은 정확 직사각형 (스플라인 둥글림 금지).
- Inside-outside 명시: 모든 피처마다 본체 / 별도·삽입 부품 / 빈 공간·슬롯, 방향 (돌출/오목/삽입)을 명시. 정면도에서 보이는 윤곽이 본체 고체라는 가정을 금지 (test1 내접/외접 오류, test2 탭/와이어 오류, 갭/중앙 덩어리 오류가 모두 같은 패턴).
- 닫힌 루프 없으면 중단, 가짜 직선 금지: 루프가 코드 없이 닫히지 않으면 모델을 만들지 않고 정확히 어떤 끝점이 안 맞는지 보고 (v8 규칙).
  사용자 승인이 있어도 결과 형태가 거부되면 승인이 결과를 정당화하지 않음 (v7 브리지 승인 → 절단 거부).
- per-sketch 게이트 + 단일 솔리드 명시 확인: harness PASS만으로는 부족, solids == 1 별도 확인 (v6 교훈).
- 사용자 눈 + 매끄러운 곡선 우선: 자동 잉크 스냅은 답이 아님 (들쭉날쭉 거부). 스냅 도구는 눈으로 지정 + 선 선택 + 끝점 편집 + 채움 확인으로 진화.
- 치수 강제 vs 잉크 충실도: 기능부는 명목 우선 (슬롯 각도 35°/55° 강제), 형상은 잉크 우선 (훅 곡선), 차이는 수치로 보고하고 사용자가 결정.
- 트레이스 즉시 저장: 사용자가 준 JSON/이미지는 즉시 파일화, 분실 주장은 기록 확인 전 금지.
- STEP 명암 렌더 + 오버레이 유지: 프리뷰는 STEP 명암 (STL 삼각선 아님), 오버레이는 단면 간선 체인 후 작도, BSpline BoundBox는 STEP/단면으로 대조.
