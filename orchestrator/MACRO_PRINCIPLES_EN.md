# Macro Basic Requirements — 8 Principles (English, DEFAULT)

Read this file every time a FreeCAD macro is generated by LLM.
This file contains principles only. No part dimension table, failure report, or previous macro code.
A macro prompt is basically: this principles file + the user's last content + drawing images.

This English version is the DEFAULT for macro prompts. The Korean version (MACRO_PRINCIPLES.md) is reference only.

Written: 2026-10-29, user-approved with 11:18 corrections, top principle added 2026-10-29, English/Korean split 2026-10-29.
Terminology: use "empty hole" for a hole, never "void".

## Top Principle: If a problem arises, guide it and ask a question

- Proceed with sketching while following the 8 principles below.
- If a problem arises during progress, do not stop silently and do not guess past it.
- Guide the problem and leave it as a question. State what, in which sketch/feature, with what error,
  what was tried, and what is needed to proceed.
- A failure message must contain, for EACH failed feature: feature name, sketch/geometry index,
  exact solver/error message, cause hypothesis (e.g. arc point order, redundant constraint),
  and a specific question or alternative. A vague "FAIL" or "multiple N" alone is NOT guidance.
- If a problem arises, propose an alternative or ask a question to solve it, then retry once after the answer.
  Do not stop silently, and do not retry endlessly without a question/answer.
- Self-fix rule (user Oct 29, 2026 17:59 EDT): code/API errors (syntax, constraint form, arc form,
  point order, Base link) are self-fixed and rerun, up to 3 attempts total, without asking the user
  between attempts. Log each fix (what changed, why, which line). On the 3rd failure, STOP and guide
  with feature name, geometry index, exact error, cause, and a specific question or alternative.
  Dimension/design questions are NOT self-fixed — ask the user immediately, do not invent.
- Ask the user only about design/dimensions that only the user knows. Do NOT ask the user about
  FreeCAD implementation methods (placement method, API names, constraint names) — those are
  program rules below, decide them internally.

## 1. Parametric tree, unconditional

- Build in Body → Sketch → Pad/Pocket order, with named features, to match the drawing in 3D.
- .fcstd is the main artifact; STEP is export only.
- No dead solid from Part.makeCylinder/makeBox/fuse/cut.

## 2. Sketch direction by vector

- When sketching, fix direction by vector, otherwise later features will shift/drift when fused.
- YZ sketch normal is +X. State where each local axis goes in global coordinates, and place
  the sketch at the segment-start X.
- Fix position with +/− signs, exactly.
  - For every sketch, state the local→global mapping with signs.
    - Example: YZ sketch: local X → global +Y, local Y → global +Z, normal → global +X.
    - Example: XZ sketch (flat cut): local X → global +X, local Y → global −Z, normal → global +Y.
      The bottom cut normal is global −Y.
  - FreeCAD DistanceX/Y note: a DistanceX/Y constraint given as (point, origin) is solved as
    point = −value. Do not assume point = value. In macro_v8 this sent rectangles to the opposite side.
  - DistanceX/Y between two points solves as second − first, do NOT negate.
    Example: from x=−1.8 to x=+1.8 needs DistanceX = +3.6, not −3.6.
    Negating it sent the profile to x=−5.4 and self-intersected the sketch.
- Origin rule: build from origin 0,0,0. Origin is the input shaft tip, +X is the output direction.
  All positions are measured from the origin with +/− signs.
  If a direction is not in the drawing, decide it while designing, flag it as provisional, and proceed.
  Do not block repeatedly on a direction the drawing does not show.
- Placement method (program rule, not a user question): use direct Placement with MapMode Deactivated,
  Placement base Vector(x_off, 0, 0) with the YZ rotation. Do NOT use AttachmentOffset for segment placement.
  AttachmentOffset is in local attachment coordinates, not global coordinates, and shifts the wrong axis.

## 3. Sketch constraints: minimum to green

- Use the minimum constraint set that turns the sketch green in FreeCAD.
- Green = fully constrained with a minimum, non-redundant set.
- Neither under-constrained (white) nor over-constrained with duplicate/conflicting constraints.
- Every constraint value must agree with the coordinates you constructed.
  A constraint that fights the geometry moves or flips the profile.
  Example: do not force 24.0° on a diagonal built at 24.04° — use the exact
  computed value or omit that constraint.
- Example: do not use Symmetric and origin Coincident together.
- Do not constrain a single point alone. A solitary point Lock is a wrong constraint.
  Position a point by reference instead: DistanceX/Y from the origin with +/− signs,
  Coincident to the origin or to another geometry, or a proper geometric relation —
  never by locking one point in isolation.

## 4. Machining with the corresponding tool

- Standard parts are made with the corresponding standard tool first, not hand-drawn approximations.
  - Gear: PartDesign InvoluteGear (e.g. makeInvoluteGear("InvoluteGear")) — reference only.
    Do not hand-draw trapezoid teeth.
    If the drawing contains a gear, make it by referring to the file named
    `GEAR_CREATION_REFERENCE.md`, which is included in the prompt
    ONLY when a gear is present, not for other parts.
- Drill, tap, and reamer features in the drawing are made with the corresponding tools.
- A tap hole is made with the tap-drill diameter, not the tap nominal diameter, and no helical thread solid.
  - Example: M1.6 tap uses drill Ø1.25, not nominal 1.6.
- A reamer hole uses the reamer diameter exactly; a drill hole uses the drill diameter exactly.
- A hole is an empty hole cut from material. Do not add a solid cylinder.
- Pocket direction must be correct. Check +X/−X direction for a YZ sketch.

## 5. If inaccurate, ask first, then proceed

- If modelling content is inaccurate, ask the user first, then proceed.
- Do not invent.
- During a macro run, leave questions in code comments / a question list, and pass them to the user.
  If a dimension is missing, ambiguous, or conflicts with the drawing/user content, do not proceed
  with an invented value as if it were a drawing dimension.

## 6. Per-feature valid/single-solid check + save code

- After every feature, check that the solid is valid and single; if null/invalid/multiple, stop.
- After each step, verify by comparing with the drawing instead of volume verification (projection/section/dimension for that feature).
- The macro must contain save/export code.
  - Without save code, no model remains when a run fails.
- On failure, save the partial diagnostic body for inspection, in addition to stopping and asking.
- Save the diagnostic body incrementally after EACH successful feature, not only in the failure handler.
  A failure-handler-only save leaves nothing when the run dies before the handler (as in macro_v13).
- All macro messages, check messages, and failure messages are in English (ASCII only),
  to exclude errors caused by Korean text encoding. Korean text is for reference only, not for macro messages.

## 7. Dimension priority + inference flagging

- Drawing and user content take priority over vision reading.
- On conflict, do not follow vision; flag it.
- A dimension the LLM infers from the drawing alone must be labelled inferred.
  - Do not present an inferred dimension as a confirmed dimension.

## 8. Stack / order

- Segments follow axis order, start = previous segment end, sum = total length.
- Sub-dimensions are measured as separately distinguished segments/measurements.
  - A sub-dimension is not only a position inside a larger segment.
  - Each sub-dimension is a separately distinguished segment/measurement.
  - Example: 7 is a 5.5 segment and a 1.5 segment measured separately, not one merged 7 segment;
    4.6 is a 0.6 segment and a 4.0 segment measured separately.
  - Do not double-count.
- A hole is an empty hole cut from material.
- Bolts are excluded from modelling and memoed.
  - A separate fastener such as a bolt is not modelled as a solid; leave a code comment/memo list
    entry "Bolt: separate fastener, modelling excluded".
- An unknown protrusion is asked about.
  - If there is an unknown protrusion, do not omit it and leave it only in a list;
    put it in the question list and ask the user. Do not invent it.

## How to apply

1. Read this file before macro generation.
2. Give the prompt this principles file + the user's last content + drawing images.
3. Do not put failure reports, a confirmed stack table, or previous macro code in the prompt,
   unless the user instructs otherwise.
4. Verification is by drawing dimension implementation, file tree, and each sketch's constraints.
   Volume equality with an existing model alone is not a pass.
