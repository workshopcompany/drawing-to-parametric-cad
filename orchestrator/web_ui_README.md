# web_ui.py 사용법

## 이게 뭔가요
run_pipeline.py를 명령창이 아니라 브라우저에서 쓰는 작은 화면입니다.
표준 라이브러리만 써서, 별도 설치가 필요 없습니다.

## 시작 방법
orchestrator 폴더( run_pipeline.py가 있는 폴더 )에서:
- Windows: `python web_ui.py`
- Mac/Linux: `python3 web_ui.py`
그 뒤 브라우저에서 http://127.0.0.1:8000/ 을 여세요.
포트를 바꾸려면 `python web_ui.py --port 8001` 처럼 실행합니다.

## 폼 항목
- 도면 이미지: 업로드하면 출력 폴더에 input_drawing.확장자로 저장됩니다.
  결과 페이지에서 브라우저로 직접 볼 수 있습니다.
- 윤곽 첨부 (선택): 윤곽 스냅 도구에서 뽑은 JSON, 또는 윤곽 이미지.
  JSON은 요약해서 LLM 프롬프트에 넣고(전체 1202점을 그대로 넣지 않음),
  이미지는 두 번째 이미지로 LLM에 보냅니다. 원본은 출력 폴더에
  outline_input.* 으로 보관됩니다.
- 부품 설명: 선택, 도면에 대한 메모를 적습니다.
- 기어 부품: 기어일 때만 체크하세요. 그때만 기어 참조가 포함됩니다.
- 출력 폴더: 기본 ./my_run_output, 서버를 시작한 폴더 기준입니다.
- freecadcmd: 기본 freecadcmd, PATH에 없으면 경로를 입력하세요.
- dry-run: API 호출 없이 프롬프트 조립만 확인합니다.
- Meta API 키: 비밀번호 칸, 저장되지 않고 이번 실행에만 쓰입니다.
  키 칸을 비우면 레포 폴더의 .env 파일 키를 씁니다. .env 만드는 법:
  .env.example을 .env로 복사하고 META_API_KEY= 뒤에 본인 키를 넣으세요.
  .env는 절대 깃허브에 올리지 마세요 (.gitignore가 막습니다).
  폼에는 .env 키 있음/없음만 표시되고, 키 값은 표시되지 않습니다.

## 먼저 dry-run부터
처음엔 dry-run을 체크하고 실행하세요. 프롬프트 조립이 되는지,
report.txt와 prompt_dryrun.txt가 출력 폴더에 생기는지 확인합니다.

## 결과 확인
실행이 끝나면 결과 페이지에 종료 코드, report.txt, guidance.txt(실패 시),
questions.txt(질문이 있을 때), 입력 이미지, 결과 프리뷰, 출력 파일
목록과 다운로드 링크가 나옵니다.
매크로에 Q1~Q9 같은 질문이 있으면, 그 질문은 questions.txt로 뽑혀
QA 탭에 그대로 보이고, 임시값으로 만든 결과는 “질문 대기 중 —
성공이 아닙니다”로 표시됩니다. 성공이 아닙니다. 답을 주고 계속
작업하세요.

## 언어: 기본 영어, 한국어로 전환 가능
기본 화면은 영어입니다. 사이드바 위의 “한국어” 링크를 누르면
한국어 화면으로 바뀌고, 결과 페이지에서도 같은 링크로 바꿀 수
있습니다 (`?lang=ko`). 다시 영어로 돌아가려면 “English” 링크를
누르세요. 언어 선택은 폼의 숨은 칸으로 실행 결과 페이지까지
이어집니다.

## 질문에 답변하고 계속 작업 (QA 탭 답변 폼)
질문이 있는 결과는 성공이 아닙니다. 배너에 “질문 대기 중 —
성공이 아닙니다”라고 뜨고, report.txt에도 “RESULT: QUESTIONS
PENDING”으로 적힙니다 (종료 코드는 0이지만 파일이 남는 이유는
만들어진 솔리드를 보관하기 위해서입니다).
질문이 있는 결과 페이지 QA 탭 아래에 답변 폼이 뜹니다. 질문별로
답을 적고 “계속 작업”을 누르면, 도면/윤곽은 이 결과에서 자동으로
가져오고, 답이 반영된 새 실행이 시작됩니다. 이전 매크로를 이어서
고치는 게 아니라 처음부터 새로 만드는 실행이고, 출력은 시간 붙은
새 폴더에 생깁니다. 기어 체크는 이전 결과(report.txt의 기어 참조
포함 여부)에서 기본값으로 가져오고, 바꿀 수 있습니다.
freecadcmd와 API 키도 다시 입력해야 합니다 (이전 값은 저장되지
않습니다). 이전 부품 설명은 자동으로 안 넘어가니, 필요하면 답변에
같이 적으세요. 답이 비어 있으면 실행하지 않습니다.
주의: 웹 UI 서버는 시작할 때 코드를 메모리에 올리므로, 파일을
교체한 뒤에는 서버를 끄고 다시 시작해야 새 화면(질문 배너, 답변
폼, 언어 전환)이 보입니다. run_pipeline은 실행 때마다 새로
읽으므로, 서버만 옛날 코드인 상태에서는 report에 질문이 찍혀도
화면에는 안 뜰 수 있습니다.
결과 페이지에는 탭(도면 인식 / 파라미터 & 3D / FreeCAD 내보내기 /
QA 로그)이 있고, 3D 뷰어(viewer3d.js, tris.json 기준, CDN 없음)로
모델을 돌려보며 확인할 수 있습니다. 프리뷰를 못 만들면(예: matplotlib
없음) Pillow 폴백(render_preview_pil.py)으로 다시 시도하고, 둘 다
안 되면 실행 자체는 실패하지 않고, 보고서에 "Previews: unavailable"
이라고만 남습니다.
결과 프리뷰(preview_iso.png, preview_main.png)는 STEP 테셀레이션에서
만든 음영 이미지로, 치수 도면이 아니라 형상 확인용입니다. .fcstd는
FreeCAD GUI로 열어 트리, 완전구속, 치수 변경 후 다시 계산되는지
확인하세요.

## 최근 실행 다시 보기
폼 아래에 최근 실행 목록이 뜹니다. 이미 끝난 출력 폴더는 재실행 없이
결과 페이지로 다시 열 수 있습니다. 읽을 수 없는 폴더가 있어도 폼이
죽지 않고 그 폴더만 건너뜁니다.

## 출력 폴더 (시간 붙은 폴더로 자동 생성)
기본값(./my_run_output)으로 실행하면, 실행 시각이 붙은 폴더
(예: my_run_output_20261030_090411)로 자동 생성됩니다. 이미 결과가
있는 폴더를 지정해도 시각이 붙은 형제 폴더로 바뀝니다. 그래서 다시
돌려도 예전 모델/보고서가 덮어씌워지지 않습니다. 빈 새 폴더를
지정하면 그 폴더를 그대로 씁니다. 날짜별 하부폴더가 아니라 시간 붙은
형제 폴더인 이유는, 최근 실행 목록이 서버 폴더 최상위를 스캔하기
때문입니다.

## 샘플 도면 (image/ 폴더, 로컬 전용)
orchestrator/image/ 폴더에 넣어둔 이미지는 폼에서 바로 미리볼 수
있습니다. 이 폴더는 기본적으로 비어 있습니다. 여기에 도면을 넣을 때는
회사 정보(로고, 회사명 등)가 있는 도면은 절대 깃허브에 올리지 마세요.
샘플 도면은 로컬 테스트용으로만 두는 것이 안전합니다.

## 아직 안 되는 것
- PDF 도면은 아직 지원하지 않습니다. PDF는 이미지(PNG/JPG)로 바꿔서
  올려주세요. 파이프라인에 PDF→이미지 변환이 없기 때문입니다.
- 외부 폰트를 불러오지 않습니다. 오프라인에서도 열리도록 시스템
  폰트(sans-serif / monospace)로만 표시합니다.

## 키 보안
키는 디스크에 저장되지 않고, 로그·URL·결과 페이지에 나타나지 않으며,
run_pipeline.py에는 환경변수(META_API_KEY)로만 전달됩니다. 키 칸이
비어 있고 .env 키도 없고 dry-run이 아니면 실행하지 않습니다.
.env 파일 자체도 다운로드로 제공할 수 없습니다 (출력 폴더 밖 파일은
다운로드가 막혀 있습니다).

## 윤곽 도구
outline_snap_tool.html을 브라우저로 열면, 도면 위에 윤곽을 직접 그려서
JSON으로 뽑을 수 있습니다. 이 파일은 test/test2_snap_tool.html의
복사본입니다. test/ 원본은 test2 당시 기록본이라 그대로 두고,
앞으로 윤곽 도구를 고칠 때는 orchestrator/ 복사본만 고칩니다.

## 솔직한 한계
이 UI는 사용자의 PC에서만 돌아갑니다. Muse가 이 PC를 조종하게 하지
않으며, FreeCAD를 대신하지도 않습니다. FreeCAD 1.1.4가 별도로
필요합니다. 실제 API 실행은 사용자의 키로 집에서 테스트해야 합니다.
