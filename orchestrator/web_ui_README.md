# web_ui.py 사용법

## 이게 뭔가요
run_pipeline.py를 명령창이 아니라 브라우저에서 쓰는 작은 화면입니다.
표준 라이브러리만 써서, 별도 설치가 필요 없습니다.

## 시작 방법
orchestrator 폴더( run_pipeline.py가 있는 폴더 )에서:
- Windows: `python web_ui.py`
- Mac/Linux: `python3 web_ui.py`
그 뒤 브라우저에서 http://127.0.0.1:8000/ 을 여세요.
포트를 바꾸려면 `python web_ui.py --port 8001` 처럼 실행합니다.

## 폼 항목
- 도면 이미지: 업로드하면 출력 폴더에 input_drawing.확장자로 저장됩니다.
  결과 페이지에서 브라우저로 직접 볼 수 있습니다.
- 윤곽 첨부 (선택): 윤곽 스냅 도구에서 뽑은 JSON, 또는 윤곽 이미지.
  JSON은 요약해서 LLM 프롬프트에 넣고(전체 1202점을 그대로 넣지 않음),
  이미지는 두 번째 이미지로 LLM에 보냅니다. 원본은 출력 폴더에
  outline_input.* 으로 보관됩니다.
- 부품 설명: 선택, 도면에 대한 메모를 적습니다.
- 기어 부품: 기어일 때만 체크하세요. 그때만 기어 참조가 포함됩니다.
- 출력 폴더: 기본 ./my_run_output, 서버를 시작한 폴더 기준입니다.
- freecadcmd: 기본 freecadcmd, PATH에 없으면 경로를 입력하세요.
- dry-run: API 호출 없이 프롬프트 조립만 확인합니다.
- Meta API 키: 비밀번호 칸, 저장되지 않고 이번 실행에만 쓰입니다.
  키 칸을 비우면 레포 폴더의 .env 파일 키를 씁니다. .env 만드는 법:
  .env.example을 .env로 복사하고 META_API_KEY= 뒤에 본인 키를 넣으세요.
  .env는 절대 깃허브에 올리지 마세요 (.gitignore가 막습니다).
  폼에는 .env 키 있음/없음만 표시되고, 키 값은 표시되지 않습니다.

## 먼저 dry-run부터
처음엔 dry-run을 체크하고 실행하세요. 프롬프트 조립이 되는지,
report.txt와 prompt_dryrun.txt가 출력 폴더에 생기는지 확인합니다.

## 결과 확인
실행이 끝나면 결과 페이지에 종료 코드, report.txt, guidance.txt(실패 시),
questions.txt(질문이 있을 때), 입력 이미지, 결과 프리뷰, 출력 파일
목록과 다운로드 링크가 나옵니다.
매크로에 Q1~Q9 같은 질문이 있으면, 그 질문은 questions.txt로 뽑혀
QA 탭에 그대로 보이고, 임시값으로 만든 결과는 “질문 대기 중 —
성공이 아닙니다”로 표시됩니다. 성공이 아닙니다. 답을 주고 계속
작업하세요.

## 언어: 기본 영어, 한국어로 전환 가능
기본 화면은 영어입니다. 사이드바 위의 “한국어” 링크를 누르면
한국어 화면으로 바뀌고, 결과 페이지에서도 같은 링크로 바꿀 수
있습니다 (`?lang=ko`). 다시 영어로 돌아가려면 “English” 링크를
누르세요. 언어 선택은 폼의 숨은 칸으로 실행 결과 페이지까지
이어집니다.

## “성공”이 아니라 “모델링 생성완료”, 도면 ↔ 모델링 매칭표
이전의 “성공” 표기는 “모델링 생성완료”로 바뀌었습니다. 게이트는
여전히 솔리드 1개 + 유효 True뿐이고, 도면과 같다는 뜻이 아닙니다.
결과 페이지에 새로 생긴 “도면 ↔ 모델링 매칭” 탭에서 표를 봅니다.
표 열: 번호 | 항목 | 도면값 | 모델링값 | 결과(O/X/?/-).
도면값은 LLM이 도면에서 읽어 매크로에 쓴 값(질문 먼저 단계의
D치수, 또는 확인된 답변)이고, 모델링값은 매핑에서 읽습니다.
만드는 LLM이 매크로 맨 위에 적는 FEATURE_MAP이 치수마다 어느
피처·스케치·kind인지를 정하고, 파이프라인은 .fcstd 피처에서 값을
읽습니다 (Pad 길이, 이름 붙인 스케치 구속, 원통 지름 등).
매핑이 없는 행은 ?가 뜹니다. O는 0.01mm 이내, X는 다름,
?는 자동 매핑 불가, ~는 참고용입니다.
도면값이 도면을 직접 측정한 진값이 아니라는 점에 주의하세요.
LLM이 도면을 잘못 읽으면 양쪽이 같이 틀릴 수 있습니다. 매칭표는
“만든 게 의도한 대로 나왔나”를 보는 것이지, “도면 진값과
같나”를 증명하는 게 아닙니다. 모델링값·실측값 셀에 마우스를
올리면 어떤 피처에서 어떻게 읽었는지 방법이 뜹니다.
결과 폴더에는 정면/평면/측면 고정 뷰 미리보기
(preview_front/top/side.png)도 같이 생깁니다.

## 번호 도면 (D1, D2, …)
질문 먼저 단계에서 LLM이 읽을 수 있는 치수를 “D1: 외경 = 22mm
@ (0.75, 0.20)” 형식으로 뽑습니다. (x, y)는 도면 이미지상의
대략 위치(0~1, 왼쪽 위 원점)입니다. 파이프라인은 그 위치에 빨간
번호 배지를 찍은 drawing_numbered.png를 만들고, dimensions.json에
목록을 저장합니다. 매칭 탭에서 번호 도면과 표를 같이 봅니다.
배지 위치는 LLM 비전 추정치라 정확하지 않을 수 있습니다. 표가
기준이고, 배지는 원본 도면과 대조해 확인하세요. 번호 도면은
질문 먼저 실행에서만 생기고, 계속 작업으로 넘어갈 때 새 폴더로
같이 복사됩니다. 예전 실행 폴더에는 번호 도면이 없습니다.

## 실패해도 이어가기 (design-question FAIL은 막다른 길이 아님)
LLM이 매크로 대신 질문만 내놓으면 파이프라인은 값을 지어내지
않고 FAIL(design question)로 멈춥니다. 모델이 없는 게 정상입니다
(잘못된 부품을 만드는 것보다 멈추는 게 낫습니다). 이때
guidance.txt에 LLM의 질문 원문이 남고, questions.txt에도 같은
질문이 남습니다. 결과 페이지 QA 탭에서 guidance를 읽고, 아래
"계속 작업" 폼에 답을 적으면 됩니다. 폼이 없는 예전 실패
폴더도 guidance만 있으면 폼이 뜹니다. 계속 작업은 새로
실행이지 이어쓰기가 아니므로, 이전 답변도 다시 붙여넣어야
합니다. 참고로 연속 계속 작업 시 폴더 이름에 타임스탬프가
계속 붙지 않도록, 기존 타임스탬프를 떼고 새로 붙입니다.

## Q&A 내역 자동 누적 (qa_history.txt) — 이전 답 다시 붙여넣기 불필요
계속 작업으로 답하면, 그 라운드의 질문+답이 새 폴더의
qa_history.txt에 누적됩니다. 다음 실행 프롬프트에는 지금까지의
전체 Q&A 내역이 자동으로 들어가므로, 매번 새 답변만 적으면
됩니다 (이전에는 바로 앞 질문+이번 답만 넘어가서 매번 전체를
다시 붙여넣어야 했습니다). 누적 내역은 결과 페이지 파일 목록에서
qa_history.txt로 확인/다운로드할 수 있습니다. 단, 계속 작업은
이전 매크로를 이어서 고치는 게 아니라 처음부터 새로 만드는
실행입니다. 모델 자체를 이어서 수정하는 기능은 없습니다.
결과 폴더 자체가 프로젝트 저장소입니다. 도면, 윤곽, 보고서,
질문, 매크로, 모델(있으면)이 폴더에 남고, 서버를 같은 폴더에서
다시 시작하면 최근 실행 목록에 그대로 뜹니다 (다른 폴더에서
시작하면 안 뜹니다 — 최근 실행은 서버 실행 폴더 기준입니다).

## 작업 폴더를 골라서 이어서 작업하기
메인 페이지 최근 실행 아래에 "작업 폴더에서 이어서 작업"
칸이 있습니다. 목록에서 폴더를 골라 "선택한 폴더 다시 실행"을
누르면 그 폴더에 저장된 도면/윤곽/Q&A 내역이 재사용돼서
도면을 다시 올릴 필요 없이 새 실행이 시작됩니다. 이전
모델을 고치는 게 아니라 새로 만드는 실행이고, 결과는 새
타임스탬프 폴더에 생깁니다. 폴더를 열어서 보기만 하려면
절대 경로 입력란이나 최근 목록의 링크를 쓰세요. 그러면
결과 페이지에 계속 작업 폼이 항상 뜹니다. 질문/안내가 있는
폴더는 답변 폼이, 질문이 없는 완료 폴더는 "이 프로젝트
이어서 작업" 폼(새 지시 입력)이 뜹니다. 주의: 선택기는 이미
결과가 있는 폴더만 다룹니다. 빈 새 폴더나 없는 경로는 열 수
없고, 원인을 구분한 에러가 뜹니다. 새로 시작하려면 폴더를
고를 필요 없이 메인 폼에서 그냥 실행하세요. 새 타임스탬프
폴더가 자동으로 생깁니다.

## 질문 먼저 (기본 켜짐) — 주고받기 순서
기본적으로 “질문 먼저”가 켜져 있습니다. 첫 실행은 모델을 만들지
않고 질문만 뽑습니다 (report에 “ASK-FIRST”, 모델 파일 없음,
배너는 “질문 대기 중” 또는 “질문 먼저 완료 — 아직 모델이
없습니다”). QA 탭 답변 폼에서 답하고 “계속 작업”을 누르면 그때
비로소 답을 반영해 만듭니다. 만드는 도중 새 질문이 생기거나
실패하면, 다시 질문이 뜨고 답하면 다시 만듭니다. 이게 주고받기
고리입니다. 질문 먼저를 끄면 예전처럼 바로 만들면서 질문을 뒤에
남깁니다.
주의: 이전 주고받기가 안 됐던 이유 세 가지가 고쳐졌습니다. (1)
질문 추출이 “Q1:”으로 시작하는 줄만 봤는데, 이제 “Question 1:”,
“Q1.”, “- Q1:” 같은 형태도 뽑습니다. (2) 답변만 프롬프트에
들어갔는데, 이제 이전 질문 목록도 같이 들어갑니다. (3) 빌드
프롬프트에 “INFERRED 값에는 반드시 Q줄을 달 것”이 추가됐고,
자가수정 시 이전 Q줄을 떨어뜨리지 않도록 했습니다. 그래도 LLM이
질문을 하나도 안 쓰면 PASS가 됩니다 — 그건 코드가 아니라 LLM이
묻지 않은 경우이고, 질문 먼저 단계에서 “NO QUESTIONS”라고
적으면 계속 작업으로 바로 만들 수 있습니다.

## 질문에 답변하고 계속 작업 (QA 탭 답변 폼)
질문이 있는 결과는 성공이 아닙니다. 배너에 “질문 대기 중 —
성공이 아닙니다”라고 뜨고, report.txt에도 “RESULT: QUESTIONS
PENDING”으로 적힙니다 (종료 코드는 0이지만 파일이 남는 이유는
만들어진 솔리드를 보관하기 위해서입니다).
질문이 있는 결과 페이지 QA 탭 아래에 답변 폼이 뜹니다. 질문별로
답을 적고 “계속 작업”을 누르면, 도면/윤곽은 이 결과에서 자동으로
가져오고, 답이 반영된 새 실행이 시작됩니다. 이전 매크로를 이어서
고치는 게 아니라 처음부터 새로 만드는 실행이고, 출력은 시간 붙은
새 폴더에 생깁니다. 기어 체크는 이전 결과(report.txt의 기어 참조
포함 여부)에서 기본값으로 가져오고, 바꿀 수 있습니다.
freecadcmd와 API 키도 다시 입력해야 합니다 (이전 값은 저장되지
않습니다). 이전 부품 설명은 자동으로 안 넘어가니, 필요하면 답변에
같이 적으세요. 답이 비어 있으면 실행하지 않습니다.
주의: 웹 UI 서버는 시작할 때 코드를 메모리에 올리므로, 파일을
교체한 뒤에는 서버를 끄고 다시 시작해야 새 화면(질문 배너, 답변
폼, 언어 전환)이 보입니다. run_pipeline은 실행 때마다 새로
읽으므로, 서버만 옛날 코드인 상태에서는 report에 질문이 찍혀도
화면에는 안 뜰 수 있습니다.
결과 페이지에는 탭(도면 인식 / 파라미터 & 3D / FreeCAD 내보내기 /
QA 로그)이 있고, 3D 뷰어(viewer3d.js, tris.json 기준, CDN 없음)로
모델을 돌려보며 확인할 수 있습니다. 프리뷰를 못 만들면(예: matplotlib
없음) Pillow 폴백(render_preview_pil.py)으로 다시 시도하고, 둘 다
안 되면 실행 자체는 실패하지 않고, 보고서에 "Previews: unavailable"
이라고만 남습니다.
결과 프리뷰(preview_iso.png, preview_main.png)는 STEP 테셀레이션에서
만든 음영 이미지로, 치수 도면이 아니라 형상 확인용입니다. .fcstd는
FreeCAD GUI로 열어 트리, 완전구속, 치수 변경 후 다시 계산되는지
확인하세요.

## 최근 실행 다시 보기
폼 아래에 최근 실행 목록이 뜹니다. 이미 끝난 출력 폴더는 재실행 없이
결과 페이지로 다시 열 수 있습니다. 읽을 수 없는 폴더가 있어도 폼이
죽지 않고 그 폴더만 건너뜁니다.

## 출력 폴더 (시간 붙은 폴더로 자동 생성)
기본값(./my_run_output)으로 실행하면, 실행 시각이 붙은 폴더
(예: my_run_output_20261030_090411)로 자동 생성됩니다. 이미 결과가
있는 폴더를 지정해도 시각이 붙은 형제 폴더로 바뀝니다. 그래서 다시
돌려도 예전 모델/보고서가 덮어씌워지지 않습니다. 빈 새 폴더를
지정하면 그 폴더를 그대로 씁니다. 날짜별 하부폴더가 아니라 시간 붙은
형제 폴더인 이유는, 최근 실행 목록이 서버 폴더 최상위를 스캔하기
때문입니다.

## 샘플 도면 (image/ 폴더, 로컬 전용)
orchestrator/image/ 폴더에 넣어둔 이미지는 폼에서 바로 미리볼 수
있습니다. 이 폴더는 기본적으로 비어 있습니다. 여기에 도면을 넣을 때는
회사 정보(로고, 회사명 등)가 있는 도면은 절대 깃허브에 올리지 마세요.
샘플 도면은 로컬 테스트용으로만 두는 것이 안전합니다.

## 아직 안 되는 것
- PDF 도면은 아직 지원하지 않습니다. PDF는 이미지(PNG/JPG)로 바꿔서
  올려주세요. 파이프라인에 PDF→이미지 변환이 없기 때문입니다.
- 외부 폰트를 불러오지 않습니다. 오프라인에서도 열리도록 시스템
  폰트(sans-serif / monospace)로만 표시합니다.

## 키 보안
키는 디스크에 저장되지 않고, 로그·URL·결과 페이지에 나타나지 않으며,
run_pipeline.py에는 환경변수(META_API_KEY)로만 전달됩니다. 키 칸이
비어 있고 .env 키도 없고 dry-run이 아니면 실행하지 않습니다.
.env 파일 자체도 다운로드로 제공할 수 없습니다 (출력 폴더 밖 파일은
다운로드가 막혀 있습니다).

## 윤곽 도구
outline_snap_tool.html을 브라우저로 열면, 도면 위에 윤곽을 직접 그려서
JSON으로 뽑을 수 있습니다. 이 파일은 test/test2_snap_tool.html의
복사본입니다. test/ 원본은 test2 당시 기록본이라 그대로 두고,
앞으로 윤곽 도구를 고칠 때는 orchestrator/ 복사본만 고칩니다.

## 솔직한 한계
이 UI는 사용자의 PC에서만 돌아갑니다. Muse가 이 PC를 조종하게 하지
않으며, FreeCAD를 대신하지도 않습니다. FreeCAD 1.1.4가 별도로
필요합니다. 실제 API 실행은 사용자의 키로 집에서 테스트해야 합니다.

## 실측 버튼과 테이블 저장 (매칭 탭)

- 실측 버튼: model.step이 있는 결과 페이지 매칭 카드에 실측 버튼이
  있어(옆에 freecadcmd 칸). 누르면 그 폴더에
  `run_pipeline.py --measure`를 돌려. API도 모델 재생성도 안 해.
  실측 후 표에 모델링값 옆 실측값 칸이 생겨(방법은 마우스 올리면
  보이고 판정은 없어). 끝나면 "실측 완료" + 시간이 떠. 다시
  누르면 이전 실측을 덮어써.
- 테이블 저장: 매칭표 모든 행 왼쪽에 체크박스가 있어(기본 전부
  체크). 표 아래에 전체 선택 / 전체 해제 버튼, 형식 선택(CSV /
  엑셀 .xlsx), 테이블 저장 버튼이 있어. 체크한 행만 저장돼. CSV는
  UTF-8 BOM이라 윈도우 엑셀에서 한글이 안 깨지고, 구글 시트에도
  바로 올릴 수 있어. .xlsx는 표준 라이브러리만으로 만들어서
  openpyxl 설치가 필요 없고, 엑셀에서 열려(시트에도 가져갈 수
  있어). 숫자는 숫자로 저장돼서 시트에서 계산할 수 있고, 빈칸은
  값 없음이야. 저장되는 칸은 번호, 항목, 도면값, 모델링값, 실측값
  (있을 때), 결과야.

실측 후 매칭표에는 판정이 두 개가 돼. Result(모델링 기반: 의도대로
만들었나, 엄격 0.01mm)와 실측 판정(실측 기반: 실제 형상이 맞나,
일반 공차 ±0.1mm)이야. 실측 판정은 Measured 옆에 보여. 그래서 어떤
행은 Result는 X인데 실측 판정은 O일 수 있어. 그 행은 모델링 매핑이
틀렸지만 실제 형상은 맞는 거야. 실측이 없는 행은 실측 판정이 ?야.
