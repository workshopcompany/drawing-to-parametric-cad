# 치수 → 피처 매핑 설계 (Dimension → Feature Mapping)

작성: 2026-10-30. 상태: **구현 완료 + 검증됨 (2026-10-30 밤)**.
배경: 숫자 주머니에서 가장 가까운 값을 고르는 방식(배터리 매칭)은
기어 D8/D9 오매칭을 낳았다. 어떤 도면에도 통하는 규칙으로 바꾸는 것이 목표다.

구현 메모 (설계안 대비 달라진 점, 테스트로 확인됨):
- `kind`는 7종이다 (`chamfer_size` 추가). `feature_extent`의 radial 축은 v1에서
  미구현이다 (축 X/Y/Z만).
- 면 대응은 "생성 면"(피처 형상 − 이전 피처 형상) 기준이며, 나중 피처에
  잘리거나 합쳐진 면은 재배치 규칙(끝면·반경·스케치 프레임)으로 찾는다.
  아래 5절 참조.
- D4 예시는 설계안과 다르다: `span` + `region: left` + 최대값은 루트(0.0032)를
  잡아서 틀렸다. 훅 팁은 곡선의 국소 최소값이라 `localmin` 모드가 정답이다.
- 뷰별 면 하이라이트 미리보기는 2단계로 미뤘다. v1은 정면/평면/측면
  고정 뷰 PNG(`preview_front/top/side.png`)만 만든다.

## 1. 핵심 원칙

- 표의 두 칸은 출처가 완전히 갈린다.
  - 모델링 칸: `.fcstd`에서 읽는다 (파라메트릭 모델이 말하는 값).
  - 실측 칸: `STEP`에서 잰다 (실제 형상을 잰 값).
- 두 칸 모두, 치수마다 "어느 피처냐"를 먼저 정하고 그 피처에서 값을 가져온다.
  숫자가 가깝다고 고르는 일은 새 방식에서는 없다.
- 매핑이 없으면 `?`로 비워둔다. 추측으로 채우지 않는다.

## 2. 매핑 형식 (mapping.json)

만드는 단계의 LLM이 매크로 맨 위에 `FEATURE_MAP` 딕셔너리(파이썬 리터럴)로 적는다.
파이프라인은 빌드 성공 후 이를 `ast`로 읽어 결과 폴더에 `mapping.json`으로
저장한다. 표는 `mapping.json`을 읽지, 매크로 글을 뒤지지 않는다.
(기존 `parse_macro_dimensions`의 `이름 = 숫자` 줄 뒤지기는 폐기한다.
실제 매크로는 치수를 튜플·계산식·속성 할당에 숨겨서 그 방식으로는 못 찾았다.)

실제 형식 (D-번호 → 항목 딕셔너리; 리스트 형태도 허용, 항목에 `no` 포함):

```json
{
  "D8": {"feature": "Pad_Step", "sketch": "Sketch_Step",
         "kind": "diameter", "view": "front"},
  "D4": {"feature": "Pad_Crown", "sketch": "Sketch_Crown",
         "kind": "span", "view": "front", "region": "leftmost",
         "extremum": "min", "localmin": true, "datum": "Pad_Base.top"}
}
```

필드 설명:

- `view`: front / top / side / section. D-줄의 `[view]` 태그에서 온다. 없으면 null.
- `feature`: `.fcstd` 안에 있는 PartDesign 피처 이름 (예: `Pad_Step`, `Pocket_Slot1`,
  `InvoluteGear`). 피처가 아직 없는 도면 읽기 단계에서는 만들 수 없으므로,
  반드시 만드는 단계의 LLM이 적는다.
- `sketch`: 그 피처를 정의한 스케치 이름. 스케치에 사는 치수일 때만 필요하고,
  피처 프로퍼티에 사는 치수면 null이어도 된다.
- `kind`: 아래 7종 중 하나. 값을 "어떻게 읽을지"를 정한다.
- `region`: 피처 안에서 부위를 가를 때만 쓴다. `left` / `right` / `top` / `bottom`
  (중심 기준 절반) 또는 `leftmost` / `rightmost` / `topmost` / `bottommost`
  (바깥 1/4 밴드). 없으면 null (피처 전체).
- `datum`: `span` 전용. `"Pad_Base.top"` / `"Pad_Base.bottom"` 형태.
- `axis`: `feature_extent` 전용 (X / Y / Z). `span`은 없으면 뷰에서 정한다
  (front/side → Z, top/section → Y).
- `extremum`: `span` 전용 (`max` 기본값 / `min`).
- `localmin`: `span` 전용 (true면 곡선 국소 최소값 모드, 아래 참조).

## 3. kind 7종과 읽는 방법

| kind | 뜻 | 모델링(.fcstd) | 실측(STEP) |
|---|---|---|---|
| `pad_length` | Pad/Pocket의 길이·깊이 | 피처 프로퍼티 `Length` | 피처 자체 끝면 오프셋을 STEP에서 재배치해 차이 |
| `diameter` | 원형 피처의 지름 | 그 피처 생성 면의 원통 지름 (유일할 때) | 그 피처 생성 반경을 STEP 원통에서 재배치 |
| `radius` | 원형 피처의 반지름 | 위 지름 / 2 | 위 지름 / 2 |
| `sketch_constraint` | 스케치 안의 치수 | 스케치에서 D-번호로 이름 붙인 구속값 | 선 구속: 선 방향×압출축 법선의 평면 쌍 거리 (스케치 프레임 폴백 포함). 원 구속: 원통 지름 |
| `feature_extent` | 피처 형상의 크기 | 그 피처 생성 면들의 축 방향 범위 | 대응된 STEP 면들의 축 방향 범위 |
| `span` | 두 위치 사이의 거리 | 부위 면들의 축 방향 극값 − datum | 동일 (datum은 재배치 우선) |
| `chamfer_size` | 챔퍼 크기 | 피처 프로퍼티 `Size` | v1 미측정 (`?`, 원뿔 면 측정 2단계) |

스케치 구속 이름 붙이기:
스케치 치수는 구속 인덱스로 찾으면 인덱스가 밀릴 때 틀어진다.
그래서 만드는 LLM은 핵심 구속에 D-번호로 이름을 붙인다
(FreeCAD 스케치 구속 이름 변경 API 사용, 예: 구속 이름 `D8`).
파이프라인은 이름으로 찾아 값을 읽는다. 이름이 없으면 그 행은 `?`이다.

`span`과 `region`, `localmin`:
팁 높이처럼 "어느 한 피처의 파라미터"가 아닌 치수는 `span`으로 처리한다.
예: 왼쪽 팁 높이 = 크라운 피처 면들 중 왼쪽 부위의 Z 극값 − 베이스 상단 평면 Z.
부위는 뷰 평면에서 피처 중심 대비 면 중심 위치로 가른다.
`span`의 datum은 베이스 상단 같은 기준 평면이며,
매핑에 `datum` 필드로 적는다 (예: `"datum": "Pad_Base.top"`).
주의: 면 bbox의 최소값은 팁이 아니다. 크라운 왼쪽 부위 면 bbox 최소값은
루트(2.8032)라서 높이가 0.0032로 나온다. 훅 팁은 바깥 곡선의 국소 최소값
(S1 곡선 (−2.247, 3.6272), S3 곡선 (2.229, 3.7558))이므로,
팁 치수는 반드시 `"localmin": true`를 쓴다. 이 모드는 피처 곡선을 순서대로
샘플링해 부위 안의 내부 국소 최소값 중 가장 낮은 값을 잰다.
밴드 최소값(경계 진입점)과는 다르다.

## 4. 모델링 칸: `.fcstd`에서 읽기

1. `mapping.json`의 `feature`가 `.fcstd`에 있는지 확인한다. 없으면 그 행은 `?`.
2. `kind`별 리더로 값을 읽는다 (3절 표).
3. 판정은 기존과 동일하게 엄격 공차 0.01mm로 O/X를 매긴다.
4. 매핑이 없는 D-행은 `?`이다. 매크로 글 뒤지기, 실린더 추측, 전체 길이 규칙으로
   메우지 않는다. (기어 D3의 "axial length → 전체 길이 14.5" 같은 규칙은 폐기한다.)

주의: 윤곽을 따라 만든 피처(브래킷 크라운)는 공칭과 미세하게 다를 수 있다
(예: 크라운 폭 4.8107 vs 공칭 4.80, 차이 0.0107).
이 경우 모델링 판정은 엄격 0.01 기준으로 X가 뜨는 것이 정상이며,
실측 판정(일반 공차 ±0.1)이 O이면 "일반 공차 안에서는 맞다"는 뜻이다.
두 판정이 다르게 나오는 것은 버그가 아니라 설계된 역할 분담이다.

## 5. 실측 칸: STEP을 뷰로 보고, 피처 면을 재기

값은 3D에서 정확히 재고, 뷰는 "어느 면을 잴지" 고르는 데와 보여주는 데 쓴다.
픽셀을 재는 것이 아니다.

1. 매핑의 `feature`에 속한 면을 STEP에서 찾는다.
   방법: `.fcstd` 피처의 **생성 면**(그 피처 형상 − 이전 피처 형상)과
   STEP 면을 표면 종류·중심·면적·(원통은 반경, 평면은 법선)으로 대조한다.
   피처는 트리 역순으로 매칭하고 STEP 면은 한 번만 쓴다.
   나중 피처가 면을 잘라내거나 합쳐서 대응이 깨지는 경우는 재배치로 찾는다:
   - `pad_length`: 피처 자체 끝면 오프셋(법선+위치)을 STEP 평면에서 찾는다
     (면적 달라도 됨. 예: 몸통 뒷면이 리세스로 잘려도 X=13 평면은 있다).
   - `diameter`/`radius`: 피처 생성 반경을 STEP 원통에서 찾는다
     (예: 보스 Ø10 원통이 리세스 안벽과 합쳐져도 반경 5.0 원통은 있다).
   - `sketch_constraint` 선 규칙: 대응 면이 모자라면 스케치 프레임
     bbox 안의 STEP 평면으로 찾는다 (베이스 측면 같은 바깥 평면은 제외됨).
   재배치로도 못 찾으면 그 행은 `?`이다 (추측 금지).
2. `view`에 해당하는 정면/평면/측면 고정 뷰 PNG를 만든다
   (`preview_front.png` = X-Z, `preview_top.png` = X-Y,
   `preview_side.png` = Y-Z). 값은 3D에서 재고 뷰는 보여주기용이다.
   뷰 안의 면 하이라이트 표시는 2단계 과제이다.
3. `kind`에 맞게 잰다: 지름은 원통 면에서, 길이는 끝면 사이에서,
   span은 뷰 축 방향 극값 차이로, region이 있으면 해당 부위 면만으로 잰다.
   면 bbox는 B-스플라인 폴 부풀림 때문에 BoundBox가 아니라
   tessellation 극값을 쓴다 (원통만 해석적 BoundBox 유지).
4. 판정은 일반 공차 ±0.1mm로 실측 판정을 매긴다 (기존과 동일).

배지 좌표 사용 금지:
번호 매긴 도면의 배지 위치(`@ (x, y)`)는 LLM 비전 추정치라 자주 틀린다
(확인된 어긋남: D3, D10/D11, D22, D5).
배지는 화면 표시용으로만 쓰고, 측정 입력으로는 절대 쓰지 않는다.
측정의 위치 기준은 매핑의 `feature` + `region` + `view`이다.

## 6. 빈틈, 폴백, 검증

- 매핑 파일이 없는 폴더(예전 결과 폴더): 재실측 시 기존 배터리 방식을 폴백으로 쓴다.
  단, 이는 구 폴더 호환용이며 새 실행에서는 쓰지 않는다.
- 매핑 파일이 있는 실행: 매핑 없는 D-행은 `?`이다. 배터리로 메우지 않는다.
- 매핑 파일이 깨졌거나 읽히지 않으면: 경고 줄을 리포트에 남기고 배터리 폴백으로 간다.
- 검증(리포트에 명시): D-번호 중 매핑된 개수, `.fcstd`에 없는 피처 이름,
  읽기에 실패한 kind, region 대응 실패. 이 목록이 보이면 LLM이 매핑을 빠뜨린 것이다.
- D-리스트에 없는 번호가 매핑에 있으면 무시하고 경고한다.

## 7. 예시 (실제 집 데이터 기준)

- 기어 D8 "top width" 16.0 → `Pad_Step`, `diameter` →
  모델링 16.0 (O), 실측 16.0 (O). 14.5는 후보에조차 없다.
- 기어 D9 "notch width" 10.0 → `Pad_Boss`, `diameter` →
  모델링 10.0 (O), 실측 10.0 (O). 라벨이 "notch"라고 적혀 있어도 피처가 보스이므로
  값은 보스 지름이다. 라벨 오류가 값을 망치지 않는다.
- 브래킷 D7 "slot width" 0.5 → 슬롯 포켓, `sketch_constraint`(구속 이름 `D7`) →
  0.5 / 0.5.
- 브래킷 D1 "top overall width" 4.8 → `Pad_Crown`, `feature_extent` 축 X →
  모델링 4.8107 (엄격 기준 X), 실측 4.811 (일반 기준 O). 이 조합은 윤곽 추적의
  정상 패턴이다.
- 브래킷 D4 "left tip height" 0.8 → `Pad_Crown`, `span`,
  `region: leftmost`, `extremum: min`, `localmin: true`,
  `datum: Pad_Base.top` → 모델링 0.8272 (엄격 기준 X),
  실측 0.8272 (일반 기준 O). 팁이 곡선 국소 최소값이라 공칭과 0.027 차이
  나며, 이 X+O 조합은 윤곽 추적의 정상 패턴이다.
  (설계안의 `region: left` + 최대값은 루트를 잡아 0.0032로 틀렸다.)

## 8. 폐기되는 것

- `parse_macro_dimensions`의 매크로 글 뒤지기 (실제 매크로에서 안 통함).
- 실린더 경쟁 패치 (2026-10-30 로컬 전용, 미푸시 — 이 설계로 대체되어 버린다).
- 배터리 숫자 맞추기 (새 실행의 실측에서는 쓰지 않음. 구 폴더 폴백으로만 남음).
- "axial/total/length → 전체 길이" 같은 라벨 단어 규칙.

## 9. 구현 순서 (완료)

1. 매핑 형식 + 빌드 프롬프트: 매크로 맨 위 `FEATURE_MAP` 작성 요구,
   스케치 핵심 구속에 D-번호 이름 붙이기 요구. ✅
2. `.fcstd` 리더 (`read_features.py`): 피처 존재 확인, kind별 값 읽기,
   mapping.json 저장, 모델링 칸 교체, 매핑 완성도 리포트. ✅
3. STEP 피처 면 대응 + 뷰 투영 (`measure_step.py` 면 덤프,
   `attribute_step_faces`, `measure_anchored`, 고정 3면 뷰): 면 대조,
   region 가르기, kind별 측정, 실측 칸 교체, 미리보기. ✅
   (뷰 안 면 하이라이트만 2단계로 남음.)
4. 폴백·검증·문서: 구 폴더 배터리 폴백, 매핑 경고, README 정리. ✅
